# かたち工房 — OpenSCADコード生成

登録・外部API・外部CDN不要の静的Webアプリです。日本語UI、寸法単位はmm。入力値を変えるとコードが更新されます。

## iPadだけで使う（GitHub Pages）

公開後のURL： **https://ikaminiature.github.io/opens-and-generator/**

公開が完了していれば、iPadのSafariでこのURLを開くだけで使えます。PC・サーバー起動・アプリ利用のためのアカウント登録は不要です。初回表示や再読み込みにはインターネット接続が必要ですが、寸法入力・コード生成・保存はブラウザ内で処理し、入力値を外部に送信しません。

1. 円柱・円盤・直方体・中空の箱から形状を選びます。
2. mmで寸法を入力します。コードが自動更新されます。
3. 「STLを保存」をタップし、確認画面が出たら「ダウンロード」を選びます。OpenSCAD用には従来の「.scad を保存」も使えます。
4. Safariのダウンロード一覧、または「ファイル」アプリのダウンロードフォルダから 寸法入りの `.stl` ファイルや `cylinder.scad` などを開けます。保存先はSafariの設定に従います。

「コードをコピー」も利用できます。コピーできない場合はコード欄を長押しして選択・コピーしてください。ホーム画面に追加する場合はSafariの共有メニューから「ホーム画面に追加」を選べます（オフライン動作を保証する機能ではありません）。

## GitHub Pagesを初めて公開する（iPadから操作可能）

この設定にはリポジトリの管理権限を持つGitHubアカウントでのログインが必要です。公開サイトを使う人のログインは不要です。

1. Safariで https://github.com/ikaminiature/opens-and-generator を開きます。
2. ファイル一覧に `index.html`、`app.js`、`generator.js`、`style.css`、`.nojekyll` があることを確認します。まだない場合は、下の「ファイルがGitHubに反映されていない場合」を先に行います。
3. リポジトリの **Settings（設定）** → **Pages** を開きます。見つからない場合は https://github.com/ikaminiature/opens-and-generator/settings/pages に直接アクセスします。必要ならSafariのメニューからデスクトップ用Webサイトを表示します。
4. **Build and deployment** の **Source** で **Deploy from a branch** を選びます。
5. **Branch** で **main**、フォルダは **/ (root)** を選び、**Save** を押します。
6. 数分待ってPages画面を再読み込みします。公開URLが表示されたら **Visit site** で開きます。**Actions** タブでも `pages build and deployment` の成功を確認できます。
7. **Enforce HTTPS** が選べる場合は有効にし、上記のHTTPS URLで開きます。

無料で公開するには公開（Public）リポジトリを使用してください。Privateの場合、無料プランではPagesを利用できないことがあります。可視性の変更はソースも公開するため、内容を確認してからGitHubの設定で判断してください。このアプリには有料サービスや有料APIはありません。

### ファイルがGitHubに反映されていない場合

作業環境からGitHubへpushできなかった場合は、作業ファイルをiPadの「ファイル」アプリに保存したうえで、GitHubのリポジトリ画面で **Add file → Upload files** を選びます。`index.html`、`style.css`、`generator.js`、`app.js`、`fitting.js`、`organizer.js`、`layout.js`、`editor.js`、`fillet.js`、`mesh.js`、`model.js`、`preview.js`、`vendor/` 内のファイル、`.nojekyll`、`README.md` を同じフォルダ構成でアップロードし、**Commit changes** でmainに保存してください。`.nojekyll` は空ファイルで、Jekyllによる加工を無効化します。隠しファイルのアップロードが難しい場合、このアプリの通常名の静的ファイルは `.nojekyll` なしでも公開できます。

### 404になる場合

PagesのBranchがmain、フォルダがrootであること、mainの直下に `index.html` があること、Actionsのデプロイが成功したことを確認します。公開直後は反映まで数分待ち、末尾の `/` を含むURLで再読み込みしてください。

## 開発時だけローカルで確認する

利用者には不要な手順です。開発時はリポジトリのディレクトリで次を実行します。

```sh
python3 -m http.server 8000 --bind 0.0.0.0
```

`http://localhost:8000` で開けます。GitHub PagesではGitHubがファイルを配信するため、このサーバーを起動する必要はありません。ビルド・npm install・環境変数の設定は不要です。CSSとJavaScriptは相対パスで読み込み、リポジトリ名を含むURLにも対応します。

## 形状と制約

- 円柱：直径、高さ
- 円盤：直径、高さ、中心穴の直径（0で穴なし）
- 直方体：幅、奥行き、高さ
- 中空の箱：外寸の幅・奥行き・高さ、壁厚、底面の厚さ。上面が開いた箱です。

すべての寸法は有限の正数（中心穴のみ0を許可）。穴は外径未満、壁厚の2倍は外寸の幅・奥行き未満、底厚は高さ未満が必要です。エラー中はコピー・保存できません。形状ごとの入力はページを開いている間保持され、再読み込みで初期値に戻ります。

「STLを保存」で直接出力してスライサーに読み込めます。OpenSCADでコードを開き、F6でレンダリングしてSTLを書き出す従来の方法も使えます。円の分割数は24・48・96（既定）・192・384から選べます。3Dプレビューは寸法の確認用です。プリンターに応じた肉厚判定は含みません。

## インタラクティブ3Dプレビュー

- 寸法を変更するとコードと3Dモデルが更新されます。エラー中はモデルを非表示にします。
- プレビュー内を1本指でドラッグすると回転、2本指を広げる・狭めると拡大・縮小できます。プレビューの外側では通常どおりページをスクロールできます。
- 「正面」は−Y方向、「上面」は＋Z方向、「側面」は＋X方向から表示します。「全体」で斜めの見やすい視点に戻せます。
- 寸法変更・画面回転・視点切り替え時にはモデルが収まる倍率に調整します。縦横高さは同じ倍率で表示し、グリッド1マスのmm数とモデル外寸を表示します。
- 単位はmm、Zが高さです。円周は選択した分割数を使い、OpenSCADコードの `$fn` と一致します。箱は上面が開き、指定した壁厚・底厚を反映します。表示位置は見やすく中央に寄せています。
- プレビューは対応する基本形状をThree.jsで描画します。任意のOpenSCADコードを実行する機能ではありません。
- Three.js 0.160.1とOrbitControlsを `vendor/` 内に同梱（MITライセンス）。CDNやビルドは不要で、GitHub Pagesのサブパスで動作します。
- WebGL対応のSafariが必要です。描画できない場合もコード生成・コピー・保存は使えます。

開発時の3D検証：静的サーバー起動後に `node tests/preview.cjs`。Chromiumで外寸・体積・貫通穴・底厚・寸法連動・4視点・タッチ回転・ピンチを検証します。iPad相当の画面幅とタッチイベントでテストしていますが、実機Safariの確認は別途必要です。

公開後はiPadのSafariで上記URLを開き、円盤を上面から見て穴があること、箱を斜めから見て開口と底があること、細長い直方体で比率が変わることを確認してください。変更前の画面が表示されたらページを再読み込みしてください。

## STLの直接保存

- 寸法を入力し「STLを保存」をタップするだけで、ブラウザ内でバイナリSTLを生成します。PC、OpenSCAD、外部サーバーでの変換処理は不要です。
- Safariのダウンロード一覧や「ファイル」アプリのダウンロードフォルダに保存できます。保存確認が出た場合は「ダウンロード」を選びます。
- ファイル名例：`disk_diameter-40_height-3_hole-10_mm_fn-96.stl`。形状・全寸法・円形の場合は分割数を含みます。
- STL形式自体に単位の規定はないため、スライサーでは **mm** として読み込んでください。表示用の縮小・移動は出力に適用せず、入力どおりの実寸で保存します。
- 円の分割数はプレビュー・STL・OpenSCADコードで共通です。大きくするほど滑らかになります。
- プレビューとSTLは `mesh.js` の同一メッシュを使います。箱を底と壁の別部品として出力せず、内部の不要な面がない一体の閉じた境界面にしています。
- 保存時に有限座標、面積ゼロ、重複面、各辺を共有する2面の方向、正の体積を確認します。STLの32bit浮動小数点で壁などがつぶれる寸法は、日本語のエラーを表示して保存しません。通常の寸法にも32bitによる微小な丸め誤差があります。
- WebGLが使えず3Dプレビューが表示できない場合でも、STLの生成・保存は利用できます。

### STL検証

```sh
node tests/stl.test.cjs
# 静的サーバー起動後（PlaywrightとChromiumを使用）
node tests/stl-browser.cjs
```

19テストで4形状（穴なし円盤、小数寸法の箱も含む）×24・96・384分割の出力バイナリを再解析。閉じた辺・面の向き・法線・ゼロ面積や重複面がないこと、実寸、理論体積との一致、穴・箱内部に材料がなく底や壁には材料があることを検証しています。ブラウザでは4形状の実ダウンロード内容、ファイル名、分割数連動、入力エラー中の保存禁止、WebGL不可時の保存を検証しています。

生成した4形状のSTLはOpenSCADで再読み込み・レンダリングを確認しました。Bambu Studioなどのスライサー、実機iPad Safari、実際の3Dプリントはこの環境では未検証です。メッシュの閉鎖性は確認していますが、プリンターごとの最小肉厚や印刷設定はスライサーで確認してください。

## 嵌合パーツモード

「嵌合パーツ」を選ぶと、円盤ベース＋凸部のパーツAと、止まり穴のある円盤ベースのパーツBを作れます。

- A/Bそれぞれのベース直径と厚さ、凸部の直径と高さ、凹部の深さ、クリアランス、穴底の最小厚さをmmで指定します。
- クリアランスは **直径差** です。初期値0.3 mm、凸部10 mmなら凹部10.3 mm。負数や0も入力できますが、干渉の可能性を警告します。プリンターの誤差・材料の収縮を計算する機能ではありません。
- 凹部は必ず止まり穴です。B厚さ−凹部深さが最小厚さ未満になる寸法や、凹部がベースより太くなる寸法はエラーにします。凸部はAのベース直径より小さくしてください。
- 「分離」ではA（金色）とB（青色）を横並びに表示します。「組み立て」ではAを180度反転し、凸部をBの穴へ向けて配置します。
- 凸部が穴より長い場合は警告し、穴底で止まる位置（ベース間に隙間がある位置）を表示します。負のクリアランス時の組み立て表示は公称寸法の位置確認用で、物理的な挿入・変形のシミュレーションではありません。
- 「AのSTLを保存」「BのSTLを保存」「AのOpenSCADを保存」「BのOpenSCADを保存」で各ファイルを個別に出力します。「コード表示・コピー対象」でA/Bを切り替えられます。
- 出力は両パーツともベース底面Z=0、凸部・凹部が上向きの印刷用座標です。組み立てプレビューの反転や位置移動はファイルに適用しません。STLはmmで読み込んでください。
- 円の分割数はA/B、プレビュー、STL、SCADに共通です。Aは接合部に内部面のない単一の境界メッシュ、Bは穴底・内壁・外壁が連続した閉じたメッシュです。

検証コマンド：`node tests/fitting.test.cjs`（20テスト）と、静的サーバー起動後の `node tests/fitting-browser.cjs`。

A/Bの実寸、閉じた辺と正しい面方向、法線、連結性、重複・ゼロ面積のないこと、体積、穴底と接合部内部、クリアランス、寸法エラー・警告、反転配置を検証しています。ブラウザではA/BのSTL・SCADの個別ダウンロード内容、組み立て・分離と色、視点切り替え、画面幅と既存モード復帰を確認しています。OpenSCADでA/Bのコードをレンダリングし、直接出力したSTLと外寸・体積が一致することも確認しました。

実機iPad Safari、Bambu Studioなどのスライサー、実印刷・実際の嵌合具合は未検証です。まず小さいテストピースを印刷し、使用するプリンターと材料に合うクリアランスを調整してください。

## 収納トレー・格子仕切りモード

1. 「収納トレー・格子」を選び、種類を選択します。「収納トレー」は底板・外周壁付き、「格子仕切り」は内部の仕切りだけです。
2. マスの内寸、横・縦のマス数（各1〜20）、仕切り厚と高さを入力します。トレーでは外周壁厚と底板厚も指定します。高さは底板上からの高さなので、トレーの総高さは仕切り高さ＋底板厚です。外周壁も仕切りと同じ高さになります。
3. 必要ならケース内寸を入力します。各項目は空欄にできます。外寸、総マス数、中央に置いたときの左右・前後の各側の余白、高さの余裕が自動表示されます。未入力の方向は未判定です。
4. ケースとのクリアランスは **左右・前後の各側の隙間** です。嵌合モードの直径差とは異なります。高さの余裕はケース高さ−生成物高さで表示します（ケース底面に置く想定）。ケース内寸やクリアランスを変えても形状は自動縮小しません。
5. プリンターの造形範囲は初期値180×180×180 mm（Bambu Lab A1 mini）です。ケースに収まらない、指定した隙間を確保できない、軸方向の造形範囲を超える場合は警告します。警告中も保存でき、自動分割や最適な印刷方向の計算は行いません。
6. プレビューで確認し、「STLを保存」または「.scad を保存」をタップします。STLはmmとしてスライサーに読み込んでください。

外寸（トレー）：幅＝横マス数×マス内寸幅＋(横マス数−1)×仕切り厚＋2×外周壁厚。奥行きも同様です。格子には外周壁がないため外縁のマスは開放され、マス数と内寸は仕切り配置の基準になります。

トレーは1×1にも対応します。格子の1×1には仕切りが存在しないためエラーです。格子で一方向だけ1の場合は平行な仕切りになり、複数本は独立した閉じた部品として出力します。その場合、外寸・余白は材料が実在する範囲から計算します。両方向2以上の格子は交差部で連続する一体構造です。

メッシュは直交格子上で材料の境界面だけを生成し、交差部や底板と壁の接合部の内部面を除去します。STLと3Dプレビューは同じメッシュを使用します。

検証：`node tests/organizer.test.cjs`（16テスト）、静的サーバー起動後の `node tests/organizer-browser.cjs`。1×1、片方向1、20×20、小数寸法で閉鎖性・面方向・法線・重複面やゼロ面積がないこと、体積、外寸、マス内部の空間、交差部と底板、ケース判定と造形範囲を確認しています。ブラウザで両種類の保存内容、20×20更新、画面幅、既存モード復帰も確認しています。

代表的なトレーと格子のOpenSCADコードを実際にレンダリングし、直接生成したSTLと外寸・体積が一致することを確認しています。既存モードの自動テストも実行済みです。実機iPad Safari、Bambu Studioなどのスライサー、実印刷・実ケースへの装着、公開サイトへのデプロイ完了はこの環境では未確認です。

## 2Dレイアウト編集

「収納トレー・格子」を選ぶと、均等配置を初期状態にした平面図が表示されます。

1. **削除・復元**：内部の壁区間をタップすると、その区間だけを削除します。点線をもう一度タップすると復元できます。隣接マスを結合して長方形やL字型の空間を作れます。外周壁は編集対象にしません。
2. **移動**：縦壁を左右、横壁を上下にドラッグします。同じ境界の残っている全区間が連動し、削除状態は保持されます。選択した境界は色を変えて表示します。
3. **数値指定**：移動モードで壁を選び、「選択した境界の位置」にmmを入力して「位置を適用」。位置は、トレーでは外周壁の内側の左端／手前端から、内部壁の始点までの距離です。格子では元の配置基準の端からの距離です。壁中心までの距離ではありません。
4. **元に戻す／やり直す**：削除・復元・移動・リセット・読み込みを履歴操作できます（最大60操作、ページ再読み込みまで）。ドラッグ1回を1操作として扱います。
5. **均等配置にリセット**：現在のマス数と内寸で均等配置に戻し、削除した壁も復元します。リセット自体も元に戻せます。

移動による最小内寸は1 mm（初期のマス内寸が1 mm未満の場合はその値）です。隣の壁と重なったり、外周を越えたりする位置は制限します。各列・行の現在の内寸と、結合後の領域数を表示します。格子は外周が開放されるため、領域数は元のマスを結合した配置上の数です。

マス数を変えた場合は境界位置を均等に再配置し、まだ存在する区間IDの削除状態を保持します。マス内寸・壁厚の変更時は可能な範囲で相対位置を保持し、最小内寸を守れない場合は位置だけ均等に戻します。外形全体の寸法は境界移動で変えませんが、外周壁のない格子の材料外寸は壁の削除・移動によって変わることがあります。

2D、3D、STL、OpenSCADは同じ編集データを参照します。交差部は隣接する壁に必要な材料だけ残し、内部面を除去します。孤立した仕切りは警告します（トレーは底板で支えられますが、格子では独立部品になる場合があります）。格子の全仕切り削除時は出力を止めますが、2D図から復元できます。

### 編集データの保存

- **ブラウザに保存**：寸法、種類、移動位置、削除状態を、このサイトのlocalStorageに保存します。同じブラウザ・同じURLのサイトで「保存を復元」を押すと再開できます。通常の編集状態はモード切り替え中も保持します。
- **JSONを保存**：設定を `katachi-layout.json` としてダウンロードします。iPadでは「ファイル」アプリに保存できます。
- **JSONを読み込む**：保存したJSONを選ぶと編集を再開できます。対応形式、寸法、境界順序、区間IDを検証してから適用します。対応バージョンは1、上限100KBです。
- ブラウザのデータ削除やプライベートブラウズでは保存が消える・使えない場合があります。残したい設定はJSONでも保存してください。履歴や選択中の壁は保存対象外です。

`layout.js` がバージョン付きの編集データと編集操作、`editor.js` がタッチUI、`organizer.js` が材料配置と出力を担当します。境界位置と区間IDを分離しており、将来の任意仕切り追加は新しいスキーマや編集操作として拡張できます。この版では既存格子の編集のみです。

### 編集機能の検証

## フィレット（段階実装）

今回対応しているのは **直方体・中空の箱・収納トレーの「外周の縦角」** です。角を丸める機能全体の第一段階で、手が触れる上端の丸めはまだ実装していません。

1. 対応形状を選び「エッジのフィレット」の「外周の縦角」をONにします。
2. 半径Rをmmで入力するとプレビューが更新されます。
3. STLまたはOpenSCADを保存します。

4項目それぞれにON/OFFと半径欄があります。半径の初期値は上端1.0、縦角2.0、底面側0.5、仕切り上端0.5 mmです。従来の形状を維持するため初期状態はすべてOFF。R0もフィレットなしです。

**未対応**：外周上端、底面側、内部仕切り上端、格子仕切りの角・T字／十字交差部のフィレット。これらをONかつR>0にすると日本語で未対応を表示し、プレビューとファイル出力を止めます。OFFまたはR0に戻すと従来機能を使えます。未対応のフィレットを別形状や近似形状に置き換えて出力することはありません。

- 縦角は外側の材料だけを除去する円弧です。幅・奥行き・高さの外寸を維持し、内壁、マス内寸、仕切り、底板厚、嵌合面は変更しません。円弧は四半円あたり24分割です。
- トレーと箱は、内部へ食い込ませないためRを外周壁厚以下に制限します。直方体は幅・奥行きの半分未満です。超過時は警告・エラーを表示し、保存を止めます。自動縮小はしません。例えば壁厚1 mmにR2 mmは使えません。
- 部分削除や移動済みのトレーレイアウトにも対応します。ON/OFF操作で削除状態・境界位置は変えません。ブラウザ保存／JSON保存にはフィレット設定も含みます。
- プレビューとSTLは同一メッシュを使用します。フィレット有効時のOpenSCADコードは、そのメッシュをそのまま `polyhedron` として記述します。解析的な円弧ではなく同じ分割済み円弧で、STLと同じ形状です。フィレットOFF時のコードとメッシュは以前のままです。
- プリンターの最小肉厚や強度を保証する機能ではありません。Rの制約内でも印刷設定に合わせて確認してください。

検証：`node tests/fillet.test.cjs`、静的サーバー起動後の `node tests/fillet-browser.cjs`。4形状についてOFF/R0同一性と対応・未対応の扱いをテストし、対応形状の閉鎖性、向きの整合した2面で共有される辺、ゼロ面積・重複面がないこと、非隣接三角形の交差、外寸、体積、内部座標、編集維持、過大Rの拒否を確認しています。代表的な3形状でOpenSCADのレンダリングと直接STLの体積一致も確認しました。これは汎用CADカーネルによる任意形状の自己交差証明ではなく、今回対応した外周縦角のテストです。
